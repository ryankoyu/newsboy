# 2. 발견된 갭·결함 (심각도순)

### G1. 운영자 검수 콘솔이 없어 "발행"이 구조적으로 불가능 🔴
파이프라인은 자동 발행 금지 원칙에 따라 기사를 `status: "review"`, 에디션을 `status: "draft"`로 저장하고, 사람이 웹 화면에서 승인하는 것을 전제로 설계돼 있다(`pipeline/src/pipeline/run.ts` 상단 주석). 그런데 `web/src/app`에는 admin·review·approve 계열 경로가 하나도 없다. 즉 **오늘 파이프라인을 돌려도 그 결과를 발행할 방법이 없다.** production-readiness가 "가장 큰 미구현 기능"으로 지목한 것과 일치하며, 출시 최단 경로의 2순위다.

### G2. 신뢰 고지가 매체 수를 부풀린다 (계획과 다르게 동작) 🔴
`web/src/components/SourcesSection.tsx`는 `const n = sources.length`로 **소스 행(피드) 수**를 세어 "이 기사는 {n}개 매체에서 교차 확인된 사실을 바탕으로…"라고 쓴다. `SourceCountBadge`의 "소스 N"도 같은 값이다. 그런데 top10-curation.md Layer 1은 "같은 매체의 다른 피드는 1개 소스로 계산"을 명시했고, 파이프라인은 이 규칙을 `outletKey`로 지키고 있다 — **웹 표시단만 이 규칙을 적용하지 않는다.**
실제 화면에서 1번 기사는 "소스 6 / 6개 매체"라고 표시하면서 출처 목록에 `The Guardian World`를 두 번 나열한다(실제 서로 다른 매체는 5곳). 현재 웹 시드 10개 기사 중 **4개**(1·2·4·9·10번 중 4건)가 같은 문제다.
enhancement-plan.md가 못 박은 "신뢰 고지 문구는 사실만 — 과장 금지"를 정면으로 어기는 지점이고, 하필 신뢰를 강점으로 내세우는 문구라 가장 위험하다.

### G3. 웹이 보여주는 에디션이 필터링 이전 데이터다 🟠
`web/src/lib/data/seed/`는 **2026-07-13 에디션**(Top10 필터링 작업을 촉발한 바로 그 편중 에디션)이다. 실화면 홈의 카테고리 구성은 **World 5 / Korea 2 / AI 2 / Culture 1** — 계획 쿼터(World 3/Korea 2/AI·Tech 2/Business 2/Culture·Sports 1)를 어기고 Business·Tech·Sports가 0이며, World 5건 중 3건이 미국 정치 인물 뉴스다.
필터링을 적용해 만든 `pipeline/output/editions/2026-07-14.json`은 존재하지만 **웹 시드로 반영되지 않았다.** 지금 화면을 여는 사람은 개선 이전 결과만 본다.

### G4. 같은 에디션을 홈은 "오늘", 뷰어는 "지난 브리핑"이라고 말한다 🟠
홈은 최신 에디션을 무조건 "Your Daily Brief — 오늘 꼭 알아야 할 뉴스 10개"로 소개한다(날짜 비교 없음). 반면 기사 뷰어는 `edition_date !== 오늘`이면 "2026년 7월 13일 브리핑" 라벨을 붙인다. 실화면에서 같은 기사가 홈에서는 오늘 것, 뷰어에서는 지난 것으로 보인다. 발행이 하루라도 밀리면 사용자에게 바로 드러나는 모순이다.

### G5. World 지역 분산 룰이 구현되지 않았다 (데드 코드 포함) 🟠
top10-curation.md Layer 1의 "World 3건은 지역 분산 지향"에 해당하는 코드가 없다. 있는 것은 동일 **국가** 상한(2건)뿐이다. `rules.ts`의 `regionOf()`는 `selectTop10.ts`가 import해 놓고 **한 번도 호출하지 않는다** — 구현하다 만 흔적으로 보인다. 더해서 국가 판정 자체가 "보도한 매체의 국적" 추정이라, 미국 매체가 보도한 유럽 사건이 미국 사건으로 계산된다.

### G6. B2 분량이 전 기사에서 목표에 미달한다 🟠
계획 분량은 B2 약 520단어(프롬프트 목표 450~520)인데, 07-14 산출물의 B2 10건은 **334~447단어로 전부 하한 미달**(평균 약 407). 1건은 CEFR 게이트에서 실제로 실패했다(338단어). 재작성 3회 재시도를 거치고도 이렇다는 것은 프롬프트나 게이트 피드백이 분량을 끌어올리지 못하고 있다는 뜻이다. "B2는 원문에 가까운 표현"이라는 레벨 차별화가 약해진다.

### G7. Top10 점수화가 계획의 절반만 돌고 있다 🟠
Layer 2의 6개 신호 중 4개만 구현됐다. **GDELT 글로벌 영향력**과 **LLM 학습 적합성·감점**이 없다. Layer 3(LLM 편집회의)은 아예 없고, LLM은 이미 확정된 10개에 선정 사유 문구만 붙여준다. 문서는 이를 "API 키 연결 시" 항목으로 뒀는데 **키는 이미 연결돼 실제 재작성에 쓰이고 있으므로**, 남은 이유는 기술적 제약이 아니라 미착수다.

### G8. 강화된 2소스 게이트로 재실행하면 현재 기사 대부분이 탈락한다 🟡
07-14 에디션은 사실 단위 강화 이전 코드의 산출물이다. 지금 기준(본문 기여 사실 최소 3개)을 적용하면 10건 중 **7건**이 보류·교체 대상이다(rank 7은 본문 기여 사실 0건인데 통과해 있다). 코드는 옳고 산출물이 낡은 것이지만, "지금 파이프라인을 돌리면 10개를 채울 수 있는가"라는 실질적 위험이 남아 있다.

### G9. Smart Dictionary에 품사 표기가 없다 🟡
a3-ui-ux.md §2-3은 "품사 + 한국어 뜻"을 명시하지만 실화면은 뜻만 보여준다. 시드 데이터에도 품사 필드가 없다. (없는 품사를 채워 넣지 않은 것 자체는 규칙 1에 맞는 처리다 — 스펙과 데이터 모델 중 하나를 정리해야 한다.)

### G10. 글자크기 팝오버가 Esc로 닫히지 않는다 🟡
`FontSizePopover`에 키보드 핸들러가 없다. 바깥 클릭(투명 오버레이)만 동작한다. 실측에서 Esc를 눌러도 오버레이가 남아 다음 버튼 클릭을 가로챘다. a3 §4-1의 "Esc 닫기" 접근성 요건에 미달한다.

### G11. Supabase·Batch API가 한 번도 실행된 적 없고, 코드 주석이 사실과 다르다 🟡
둘 다 완성·단위 테스트까지 됐지만 실행 기록은 전부 `storage: local-file`, `usedBatchApi: false`다. 더해 `pipeline/src/index.ts`의 주석은 Supabase 어댑터를 여전히 "미구현 스켈레톤, 호출 시 예외"라고 설명한다 — 497줄 구현이 끝난 지금은 틀린 설명이고, 다음 사람을 오도한다.

### G12. 큐레이션 단어가 레벨당 5개뿐이라 대부분의 클릭이 "뜻 준비 중"이다 🟡
B1 본문 약 270단어 중 뜻이 있는 단어는 5개다. 실측에서 `congressman`(A2에는 뜻이 있는 단어)을 B1 본문에서 누르면 "뜻 준비 중이에요"가 뜬다. 동작은 설계대로지만, 체감상 사전이 거의 비어 있다. 이것을 메우는 것이 §4.9(기사 전체 사전)이며 현재 보류 상태다 — 즉 **보류의 대가가 사용자에게 가장 크게 드러나는 지점**이므로 해제 우선순위 판단에 참고할 것.

# 4. 이 문서를 쓰는 법

1. 기능을 새로 만들면 해당 영역 표에 **한 줄 추가** — 기능명 / 계획 출처(문서§) / 상태 / 확인 방법 / 비고.
2. 상태를 ✅로 올릴 때는 "코드가 있다"가 아니라 **실제로 동작을 봤다**를 기준으로 한다. 사용자 대면 기능이면 실화면, 파이프라인이면 산출물.
3. △로 둘 때는 **무엇이 부족한지**를 비고에 반드시 적는다. "부분 구현"만 적힌 줄은 다음 사람에게 아무 정보도 주지 않는다.
4. 갭을 고치면 §2에서 지우지 말고 **해결 표시와 날짜를 남긴다** — 왜 그런 결정을 했는지가 다음 판단의 근거가 된다.
5. 보류를 해제하면 §3에서 §1로 옮긴다.

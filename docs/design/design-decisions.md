## 4.6 QA 후 정책 확정 (2026-07-10, Q1·Q2 검수 반영)

- **온보딩은 강제하지 않는다.** 홈 즉시 열람(비로그인 열람 원칙 §4-3과 일치), 레벨 미설정 시 홈 상단 배너로 레벨 진단 유도, 기본 레벨 A2.
- **단어-본문 일치를 파이프라인이 보장한다.** 레벨별 단어는 해당 레벨 본문에 실제 등장해야 하며, 게이트로 검사한다. (Q2 발견: 시드에서 A2 본문 클릭 가능 단어 0건)
- DB 본문은 문장 단위 JSONB 활성화 (§2-3 재확인 — 스키마 주석 해제).

## 4.7 마이 페이지·학습 데이터 확장 (사용자 요청, 2026-07-13)

- **Saved 탭 → "My"(마이) 페이지로 확장**: 프로필 요약(레벨·읽은 기사·저장 수) + 3개 서랍 — 스크랩(기존 북마크) / 단어장(단어·관용구, 다단어 표현은 "표현" 배지) / 문장(저장한 문장 + 출처 기사 링크). 하단 탭은 Home/My/Settings 유지.
- **문장 저장**: 기사 본문에서 문장(단어 스팬 외 영역) 탭 → 문장 액션 팝오버(저장/해제). 저장 문장은 본문에서 표시.
- **저장 단어 본문 표시**: 이미 저장한 단어는 본문 재방문 시 구분 스타일.
- 데이터는 SessionStore(localStorage) 확장 → 로그인 도입 시 Supabase로 이관. 스키마에 saved_sentences 테이블 추가 (0002 마이그레이션, RLS 본인만).

## 4.8 사용자 피드백 반영 (2026-07-13)

1. **모든 단어 클릭 가능**: 사전에 있는 단어 = 전체 정보 + 저장. 사전에 없는 단어 = 최소 카드(단어 + "뜻 준비 중" + 저장 버튼). 없는 뜻을 지어내지 않는다 — 뜻 없이 저장되면 단어장에 "뜻 미등록" 표시, 향후 사전 API/LLM 연동 시 채움. 저장 버튼은 눈에 띄는 주 버튼으로.
2. **레벨 기본값**: 온보딩 완료자는 진단 레벨로 열림(기존 동작 유지) — 이 흐름을 자동 테스트로 고정.
3. **핵심 단어 인라인 뜻(루비)**: 어렵지만 기사 이해에 필수인 단어(isKey)는 본문에서 단어 아래 작은 한글 뜻 표기. 하단 단어 목록과 병행.
4. **콘텐츠 원칙 — 어휘 회피로 핵심 정보 누락 금지**: A2로 낮춰도 "누가 무엇을 했는가"의 무엇이 빠지면 안 된다. 어려운 핵심 단어는 유지하고 isKey로 표시해 루비로 받친다. (발견 사례: rank4 수출 기사 A2에 semiconductors 누락) 재작성 프롬프트에 규칙 반영.

## 4.9 기사 전체 사전 — 계획만 확정, 구현 보류 (2026-07-13 사용자 지시)

- 구조: 발행 시점에 파이프라인이 기사 본문 전체 단어의 사전(문맥 맞춤 뜻+IPA)을 생성해 저장. 조회 체인 = 큐레이션 단어 → 기사 사전 → "뜻 준비 중".
- **현 시점 구현 보류**: 목업(현재 에디션)에 수작업으로 단어를 채우지 않는다 (토큰 절약). API 키 연결 후 파이프라인 사전 생성 단계로 구현.
